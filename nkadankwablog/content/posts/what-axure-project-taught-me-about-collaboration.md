We recently used Axure RP 11 to create a group prototype. The software was part of the assignment, but what i learnt from it is how the members in teh group can either break or make the collaboration

## A shared file is not automatically shared work

A prototype contains screens, links, components, notes, and decisions that affect one another. If everyone edits without agreeing on names, structure, or ownership, the group can create several versions of the same idea. If only one person understands the file, collaboration quietly becomes one person's project with an audience.

The work moved better when responsibilities were clear and decisions were visible. Someone could focus on a flow or component without losing sight of how it joined the rest. Feedback also became easier when it described a specific interaction instead of arriving as “make it better.”

## The group affects the difficulty of the tool

Axure RP itself has a learning curve, but a cooperative group can spread that learning. People share discoveries, raise problems early, and ask for help before a deadline. In a difficult group, the same tool feels harder because every technical question is mixed with uncertainty about who is doing what.

The lesson I want to carry into future software projects is that collaboration needs its own design. A Git repository, shared prototype, or group chat provides a place to work, but it does not create trust, communication, or consistency.
