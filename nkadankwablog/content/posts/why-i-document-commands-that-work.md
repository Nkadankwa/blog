I can be forgetful, especially with commands I use only occasionally. When one finally solves a problem, I put it in my notes.

Saving the command protects me from repeating the same search a few weeks later. I also record what it did, where I ran it, and any part that must change on another machine. A line of shell syntax without context can be dangerous or useless when I return to it.

## My notes are temporary support

I use a personal rule for these entries. A command stays in the notes while I do not understand it well enough or have not used it often enough to remember. Repeated use gradually makes the command familiar. Once it has become part of how I work, I can remove the reminder from the learning list.

Deleting an entry does not mean documentation has no value. Project-specific setup still belongs in a README or another durable place where someone else can find it. My temporary note serves a different purpose: it holds knowledge while I am still turning it into a habit.

## A working command still deserves inspection

I avoid saving a command as a magical fix. I break down its flags, check which files it changes, and consider whether it needs elevated permissions. Commands copied from a forum, video, or AI answer can produce the expected result while also doing something I did not intend.
Eventually the command graduates from the list because I can explain and use it confidently. Until then, writing it down gives my memory somewhere reliable to continue from.
