The next phase of my homelab journey was supposed to be simple: spend time with Linux, get comfortable in the terminal, and build confidence one command at a time. I made progress—but the conditions changed before I could settle into the routine.

I had to lend my main computer to a friend, which paused the hands-on work. I did not want that to become a pause in learning, though, so I looked for a smaller and more realistic place to continue.

Instead of stopping completely, I decided to set up a “pre-homelab environment”-called Preparatory Homelab hiatus- on my personal laptop using Docker Desktop. This setup allows me to keep learning and experimenting while I wait to get my hardware back.

The installation process was surprisingly smooth, especially if you follow the official documentation. The docs guide you step-by-step through installing WSL and WSL2, then setting up Ubuntu—which is required for running Docker Desktop properly.

Since I no longer have direct access to my main device, I’ve shifted my focus to daily Linux command practice. I’ve been using cmdchallenge.com
 and aiming to complete at least one challenge each day. For any command I don’t understand, I take the time to research it and understand how it works.

**🧩 Helpful Resources for Learning Linux and Docker**

Here are a few resources that have been really useful in this phase of my learning journey:

- cmdchallenge.com – Great for daily command-line exercises.

- Linux Journey – Learn Linux concepts step by step.

- Docker Docs – The best guide for installing and running Docker properly.

- OverTheWire: Bandit – A fun, hands-on way to practice Linux commands in real environments.

**💡 Lessons Learned So Far**

- Even when obstacles appear, there’s always a workaround.

- Reading the official documentation matters. AI tools are helpful, but they sometimes give outdated or incorrect steps.

- Practicing a little every day helps keep your skills sharp—even without access to full hardware.

**What’s Next**

- Once I get my main computer back, I plan to:

- Revisit the Linux installations I started earlier.

- Continue experimenting with Docker Compose setups.

- Try setting up my first lightweight containerized service—probably something simple like a local wiki or file server.

**✨ Final Thoughts**

This phase of the journey reminded me that learning doesn’t always require perfect conditions. I know this sounds cliche but even when progress slows, consistency keeps the momentum alive. A pause isn’t the end—it’s just a redirection.
