Publishing a personal website does not have to begin with renting a server. GitHub Pages, Cloudflare Pages, and Vercel all offer ways to put a site online without paying at the beginning, but they encourage slightly different workflows.

## GitHub Pages: a clear home for a static site

GitHub Pages makes sense when the site can be built into static HTML, CSS, and JavaScript. Keeping the source in a repository also gives the project version history. For a blog generated by Hugo, that separation is easy to understand: I edit the content, build the site, and publish the output.

The main limitation is also its strength. It is not a general server where I can run any backend process I want. A static personal site, documentation page, or portfolio fits it better than an application that needs a long-running database connection.

## Cloudflare Pages: static publishing close to a wider platform

Cloudflare Pages also works well with repository-based deployments. It is attractive when I may later want to connect the site to other Cloudflare services, use a custom domain, or experiment with small server-side functions without managing a traditional server.

## Vercel: convenient previews for web projects

Vercel is particularly comfortable for framework-based projects. Preview deployments can give each change its own URL, which is useful when checking a design before making it the public version. The convenience can also make a project depend on platform-specific behaviour, so I would understand the build and export process instead of treating deployment as magic.

Free plans and limits change, so I would check each provider's current documentation before committing a busy or commercial project. For a personal site, the better question is is which service matches the site's architecture, makes updates understandable, and lets me move the site later if my needs change.
