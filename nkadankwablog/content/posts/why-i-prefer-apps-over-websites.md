One of my frustrations with Windows software is how many installed “apps” are websites wearing desktop clothes. They can be useful and easier for developers to release across platforms, but the trade-off becomes obvious on a laptop with limited memory, storage, or connectivity.

## The cost of carrying a browser inside every app

Web-based desktop apps can bring their own rendering engine and supporting processes. When several are open, the memory use can feel out of proportion to what they do. A simple chat, notes, or music interface should not always feel like another full browser session.

Connectivity is the other issue. Some applications show a desktop icon but become nearly empty when the internet disappears. A native or genuinely local tool is more likely to keep its core functions available, store work predictably, and integrate with the operating system without sending every action through a service.

## Web technology is not automatically bad

I understand why developers choose it. One codebase can reach several operating systems, updates can arrive quickly, and web skills are widely available. Some web-based apps are efficient and support offline work well. A badly written native application can waste resources too.

My preference is therefore about behaviour rather than the technology label. If an installed application handles local files, remains useful offline, starts quickly, and does not consume excessive resources, I do not care which framework produced its interface.

What bothers me is when an app asks for the privileges and storage of installed software while offering no more independence than a browser tab. I install an application because I expect it to belong on my computer. At minimum, its most important features should respect the computer it is running on.
