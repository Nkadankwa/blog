I recently came across a Twitch stream where the main event was simply a developer coding a game. There was no face camera competing for attention. The screen, the code, the game, and the chat were enough.

I found that inspiring because I do not particularly like showing my face. Online creation can sometimes make it seem as if the person has to become the product. This stream showed another possibility: the work itself could be visible while the developer kept a boundary around their identity.

## The interesting part was the process

The game did not appear fully formed. Viewers could see decisions being made, problems being worked through, and feedback arriving from chat. The chat can react to an idea while it is still flexible, and the developer can decide which suggestions serve the game rather than waiting for a finished release.

What also stood out was seeing someone work through the code manually during a period when AI-generated code is everywhere. That is not an argument that a developer must avoid AI to be legitimate. The inspiring part was that the reasoning remained visible.

## A form of building in public that fits me

I often associate “building in public” with speaking to a camera or constantly promoting progress. A quiet coding stream offers a different model. A creator can share the screen, explain when useful, collect feedback, and let the project carry the session.

I did not record enough information to identify the streamer confidently, so I am not attaching a name or game to the story. The useful discovery was the format itself: it made game development look patient, social, and possible without requiring the developer to perform a different personality for the camera.
